# Dependency pins

The monthly update agent (`.github/workflows/deps-update.yml`) updates every npm package each
month and tries every new major version. It follows this file: a package listed here is only
upgraded as its rule says. Anything not listed is fair game.

Keep this list short: a pin is a decision, not a way to postpone work. A major that merely fails
is retried next month without being pinned. The owner edits this file (docs-only, straight to
`main`); the agent never does.

| Package       | Where                 | Rule                                                                                                                                                    | Why                                                                                                                                                                                                                                                 |
| ------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@types/node` | all                   | Same major as the Node runtime (`.nvmrc`, `deploy/*.Dockerfile`), never newer. Bump it together with a Node upgrade.                                    | Newer types let `tsc` accept APIs that throw at runtime in production (#83).                                                                                                                                                                        |
| `camelcase`   | `packages/horizon-be` | Stay on 6.x.                                                                                                                                            | It generates the keys `/api/v1` returns for `format=camelCase`; newer majors change them (checked on 10: `_id` stays `_id`, `userIDs` becomes `userIds`; #82). Changing it is an API change: owner decision, with tests pinning today's keys first. |
| `snake-case`  | `packages/horizon-be` | Stay on 3.x.                                                                                                                                            | 4.x is deprecated ("Use change-case"), and it generates the `format=snakeCase` keys (#84). Replacing it with `change-case` is its own change, with tests that keep the keys the same.                                                               |
| `typescript`  | `examples/angular`    | Only versions the installed Angular accepts (`@angular/build` and `@angular/compiler-cli` `peerDependencies`). Upgrade Angular and TypeScript together. | Angular 22's build tools need TypeScript 6.0 and can't load TypeScript 7 (#76).                                                                                                                                                                     |
| `typescript`  | `packages/horizon-be` | Only versions `@nestjs/cli`/`ts-jest` support.                                                                                                          | Build and tests use the TypeScript compiler API.                                                                                                                                                                                                    |
