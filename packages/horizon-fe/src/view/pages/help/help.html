Getting started

InvokeDB gives you data tables you edit like a spreadsheet and read and write from your own code through an HTTP API. There's no server or database for you to run.

1. Make an account

Sign up with an email and password, or with Google or GitHub. With an email, confirm it with the link we send you: until then you can look around, but you can't create tables or use an API key.

2. Make a table

On the Tables page, click + and pick how to start: an empty table, a template with sample data, a CSV file, a URL or Google Sheet, or (with AI) a description. See Tables and columns and Importing data.

3. Make an API key

On the Account page, under API Keys, click New key. Copy it: it's shown only once. See API keys.

4. Call the API

Read the first rows of a table called people: 

curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.invokedb.com/v1/get?table=people&skip=0&limit=10"

Each table's API button (on the grid's top bar) shows ready-made examples for that table, in curl, JavaScript and Python. See The API.

The onboarding checklist

A new account sees a checklist on the Tables page that walks through these steps, ending with a command you can run. It ticks itself off as you go, and you can dismiss it at any time.

Tables and columns

Making a table

On the Tables page, click + and choose:

  • Empty Table: three columns and three rows to start from.
  • Table from Template: a ready-made table (a CRM, a task list, an inventory...) with sample rows you can keep or delete.
  • Table from CSV and Table from URL or Google Sheet: see Importing data.
  • Table from a Description (AI): describe the table and the AI suggests its columns and some rows; you check them before the table is made. See Ask AI.

Tables are listed on the left. Select some with their checkboxes to rename or delete them. A table's name is what the API calls it, so renaming a table changes the table your code sends.

Editing

Click a cell to edit it. Add Row on the grid's top bar adds rows, which are saved when you click the save button. Type in the filter row under the headers to filter, and click a header to sort. Refresh reloads the rows.

Columns

Click Edit Columns to add, rename, delete and retype columns, then save. In this mode each header has a type badge to pick the column's type, and an button that turns on an index, so API queries that filter on that column stay fast on big tables. The type decides how a column is filtered, sorted and checked:

  • Text (" "): any text.
  • Number (#): numbers only.
  • True/false (T/F): yes or no.
  • Date: a date, written like 2026-01-15.
  • Link: rows of another table. See Link columns.

Schema diagram

The diagram button next to + draws every table as a card with its columns, with arrows for link columns. It also suggests links it can guess from column names (a column called customer id next to a customer table).

Importing data

From a CSV file

Click +, then Table from CSV, and choose the file. The first line is the column names. The table is filled in the background; the grid says when it's done. You can also Upload a CSV into an open table.

From a URL or a Google Sheet

Click +, then Table from URL or Google Sheet, and paste a link to:

  • a Google Sheet shared as "Anyone with the link can view" (the first sheet is imported, or the one the link points at), or
  • any public URL that answers CSV, or JSON (an array of objects, which become rows).

The download can be up to 10 MB and must finish within 30 seconds. Links to private or local addresses are refused.

Keeping it in sync

A table imported from a URL has a Sync button. Sync it by hand or every hour or day, in one of two ways:

  • Replace: the table becomes exactly what the URL holds now.
  • Upsert on a key column: rows whose key matches are updated, new keys are added, and rows the source no longer has are kept.

A sync checks everything before it writes anything, so a bad download leaves the table as it was.

Link columns

A link column points at rows of another of your tables, like the customer of an order. Change a column's type to Link, pick the table it links to and the column to show for each linked row.

Click a link cell to pick rows. A cell can link to several rows. In the API the cell is an array of the linked rows' _id values (or null); add expand=<column> to a Get, Search or Query call to get the linked rows themselves.

When rows or tables are deleted

  • Deleting rows removes them from every link that pointed at them.
  • Deleting the linked table empties those cells and turns the link columns into text columns.

Link columns are left out of forms.

The API

Every table can be read and written at https://api.invokedb.com/v1. Send your API key as Authorization: Bearer YOUR_API_KEY, and name the table with ?table= (its name, any case).

Call What it does
GET /get Rows, paged with skip and limit
POST /search Rows matching simple column filters
POST /query Rows with filters (eq, ne, gt, gte, lt, lte, contains, in, empty), sort, chosen fields and cursor paging
POST /count How many rows match the same filters
POST /create Add rows (an array of objects)
PUT /update Change rows, each with its _id
POST /delete Delete rows (an array of _ids)
GET /openapi The table's OpenAPI 3 spec

An example query

curl -X POST -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  "https://api.invokedb.com/v1/query?table=people" \
  -d '{"filters": [{"column": "age", "op": "gte", "value": 21}],
       "sort": ["-age"], "limit": 50}'

The answer is { "data": [...], "next_cursor": "..." }. Send the same body with cursor set to next_cursor for the next page; next_cursor is null on the last one.

Docs for each table

In the app, a table's API button shows its own endpoints, its columns and their types, examples in curl, JavaScript (fetch and the invokedb npm client) and Python, a Try it button, and its OpenAPI spec for tools like Postman. The Api page in the app's menu documents every call in full.

Errors

A bad request is answered with a 4xx status and a message saying what's wrong (a missing table, an unknown column, a value of the wrong type). A 403 means the key can't do that, or a limit was reached.

API keys

A key lets code use your tables through the API. Make them on the Account page under API Keys. You can have up to 20 live keys, for example one per app or integration.

Making a key

  • Name: to tell your keys apart.
  • Access: Read only (get, search, query, count) or Read and write (also create, update and delete).
  • Tables: every table, or only the ones you pick. Calls on other tables are refused.

The key is shown once, when you make it. We only keep a fingerprint of it, so we can't show it again: if you lose it, make a new one.

Keeping keys safe

Treat a key like a password. Don't put a read-and-write key in a web page or a mobile app, where anyone can read it; use a read-only key limited to the tables the page needs, or call the API from your server.

Revoking

Revoke stops a key at once. Revoked keys are hidden behind a toggle and removed after 7 days.

Webhooks

A webhook tells your server when rows change. Open a table, click Webhooks, give the URL to call and pick the events: row.created, row.updated and row.deleted. Changes made in the app, by the API and by forms are sent; CSV uploads and URL syncs aren't.

What's sent

A POST with a JSON body:

{
  "id": "whd_...",
  "event": "row.created",
  "created_at": "2026-11-25T10:00:00.000Z",
  "webhook_id": "wh_...",
  "table": { "id": 11, "name": "people" },
  "rows": [{ "_id": "...", "name": "Ada", "age": 36 }]
}

A change to more than 100 rows is sent as several deliveries. Send test event sends a ping event with no rows.

Checking the signature

Each delivery has an InvokeDB-Signature: t=<unix time>,v1=<hex> header. v1 is the HMAC-SHA256, with the webhook's secret (whsec_..., shown in the dialog), of <t>.<raw body>. Compute it, compare, and reject deliveries whose t is more than 5 minutes off. 

const crypto = require('crypto');

function verify(secret, raw_body, header) {
  const parts = Object.fromEntries(header.split(',').map(p => p.split('=')));
  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${parts.t}.${raw_body}`)
    .digest('hex');
  const fresh = Math.abs(Date.now() / 1000 - Number(parts.t)) < 300;
  const a = Buffer.from(expected);
  const b = Buffer.from(parts.v1 || '');
  return fresh && a.length === b.length && crypto.timingSafeEqual(a, b);
}

Retries and the log

Answer with any 2xx status within 10 seconds. Otherwise the delivery is tried again after 5 s, 30 s, 2 min, 10 min, 1 hour and 6 hours (7 tries), then marked failed. The dialog shows each webhook's last 50 deliveries, kept for 7 days. Webhooks can't call private or local addresses, and redirects aren't followed.

Forms

A form is a public page that adds a row to a table each time someone fills it in, with no account needed. Open a table and click Forms.

Setting it up

  • A title, a description, and the columns to ask for, each with its own label, a line of help and whether it's required.
  • The submit button's text, and a thank-you message or a URL to send people to afterwards.
  • Open or closed: a closed form says so and takes no answers.

Answers are checked against the column types (a number for a Number column, a date for a Date column). Link columns aren't asked for.

Sharing

Each form has a link (/f/...) to share, and code to embed it in your own site in an iframe. Deleting the form or its table turns the link off.

Spam

Forms have a hidden field that bots fill in and people don't, and limit how often one visitor, and everyone together, can submit. Submissions count against the table's row limit and trigger its webhooks.

Views

A view is a saved way of looking at a table. Open the Views menu on the grid's top bar, then Save or manage views.... All rows goes back to the plain grid. A table can have up to 50 views.

  • Grid: the grid's current filters, sort and hidden columns, saved under a name.
  • Kanban: a card per row, in a column per value of a text or number column (a status, say). Drag a card to another column to change that value.
  • Chart: a bar, line or pie chart that counts rows, or sums a number column, per value of a column.
  • Calendar: rows on a month calendar by a date column.
  • Map: rows as points, from a latitude and a longitude number column. Each point links to OpenStreetMap; rows without a position are counted but not drawn.

Every view can have filters of its own.

Ask AI

Open a table and click Ask AI to work with it in plain English. The AI reads your columns and, only when it needs them, some rows. It can:

  • Answer questions: "How many orders over $100 came from Paris?" It runs a query and shows it, so you can check its answer.
  • Propose rows: "Add 20 sample customers." The rows appear in the grid as new rows; nothing is saved until you click Save.
  • Edit rows: "Capitalise the city names" or "Set status to done where due is before today." You see every row before and after first, and can undo the last edit.

Table from a Description (AI), under + on the Tables page, designs a new table, with columns and sample rows, from a sentence.

Allowance

Each plan includes a number of AI questions and AI rows a month (the Free plan: 10 questions and 50 rows). The dialog shows what's left. AI needs a confirmed email address. AI can make mistakes: check its answers and edits before you rely on them.

Your account

Signing in

Sign in with your email and password, or with Google or GitHub. Forgot your password? Reset it by email.

Confirming your email

After signing up with an email we send a link to confirm it (it works for 24 hours). Until then a banner in the app offers to send it again, and you can't create tables or use API keys. Accounts made with Google or GitHub are confirmed already.

The Account page

In the app, the account menu at the top right (your initial and email) opens Account settings, your API keys, Contact support and Sign out. Account settings shows your plan and your details, and lets you change your password, turn on two-factor sign-in, export your data or delete the account. Deleting it removes every table and row and can't be undone.

Getting help

Use the contact form (Contact support in the account menu opens it too), or the help button next to it for these pages.

Limits

How many tables you can have, how many rows each can hold and how many API calls you can make depend on your plan: see Pricing. A call that would go over a limit is refused with a 403 and a message saying which.
