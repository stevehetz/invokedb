Getting started

InvokeDB is a database for you and your AI agents: tables you edit like a spreadsheet, that your code and your agents read and write through an HTTP API, with AI built in to query, fill and clean them up. There's no server or database for you to run.

1. Make an account

Sign up with an email and password, or with Google or GitHub. With an email, confirm it with the link we send you: until then you can look around, but you can't create tables or use an API key.

2. Make a table

On the Tables page, click + and pick how to start: an empty table, a template with sample data, a CSV file, a URL or Google Sheet, or (with AI) a description. See Tables and columns and Importing data.

3. Make an API key

On the Account page, in API keys, click New key. Copy it: it's shown only once. See API keys.

4. Call the API

Read the first rows of a table called people: 

curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.invokedb.com/v1/get?table=people&skip=0&limit=10"

Each table's API button (on the grid's top bar, or under its … menu when the table is narrow) shows ready-made examples for that table, in curl, JavaScript and Python. See The API.

The onboarding checklist

A new account sees a checklist on the Tables page that walks through these steps, ending with a command you can run. It ticks itself off as you go, and you can dismiss it at any time.

Try the demo

Try the demo on the home page opens the app in a throwaway account of your own, with no email or password. It's already filled with a small company's tables, made up for the demo: customers, products, orders (linked to a customer and a product) and events.

What to look at

  • Views on the grid's top bar: orders on a kanban board by status, revenue by month on a chart, big orders in a filtered and sorted grid, events on a calendar and customers on a map.
  • Link columns: an order's customer and product. The tree's diagram button draws how the tables link.
  • A form on customers (the grid's Forms button): its public link adds a row.
  • An AI column: each customer's segment, read from their notes, already filled.
  • History (More → History) with the edits made when the demo was set up.
  • Ask AI, with a small allowance: 3 questions and 20 rows.

What's off in the demo

API keys and the MCP server, webhooks, imports from a URL, data export, two-factor sign-in, plans and billing, and email. The demo has room for 10 tables and 2,000 rows.

When it ends

A demo is deleted 24 hours after it's made, with everything in it. To keep your own data, sign up: that starts a new, empty account (the demo's tables aren't carried over). You can make up to 3 demos a day; when many people are trying it at once, the demo may be busy for a while.

Tables and columns

Making a table

On the Tables page, click + and choose:

  • Empty Table: three columns and three rows to start from.
  • Table from Template: a ready-made table (a CRM, a task list, an inventory...) with sample rows you can keep or delete.
  • Table from CSV and Table from URL or Google Sheet: see Importing data.
  • Table from a Description (AI): describe the table and the AI suggests its columns and some rows; you check them before the table is made. See Ask AI.

Tables are listed on the left. Select some with their checkboxes to rename or delete them. A table's name is what the API calls it, so renaming a table changes the table your code sends.

Editing

Click a cell to edit it. Add Row on the grid's top bar adds rows, which are saved when you click the save button. Type in the filter row under the headers to filter, and click a header to sort. Refresh reloads the rows.

Columns

Click Edit Columns to add, rename, delete and retype columns, then save. In this mode each header has a type badge to pick the column's type, and an button that turns on an index, so API queries that filter on that column stay fast on big tables. The type decides how a column is filtered, sorted and checked:

  • Text (" "): any text.
  • Number (#): numbers only.
  • True/false (T/F): yes or no.
  • Date: a date, written like 2026-01-15.
  • Link: rows of another table. See Link columns.

Schema diagram

The diagram button next to + draws every table as a card with its columns, with arrows for link columns. It also suggests links it can guess from column names (a column called customer id next to a customer table).

Importing data

From a CSV file

Click +, then Table from CSV, and choose the file. The first line is the column names. The table is filled in the background; the grid says when it's done. You can also Upload a CSV into an open table.

From a URL or a Google Sheet

Click +, then Table from URL or Google Sheet, and paste a link to:

  • a Google Sheet shared as "Anyone with the link can view" (the first sheet is imported, or the one the link points at), or
  • any public URL that answers CSV, or JSON (an array of objects, which become rows).

The download can be up to 10 MB and must finish within 30 seconds. Links to private or local addresses are refused.

Keeping it in sync

A table imported from a URL has a Sync button. Sync it by hand or every hour or day, in one of two ways:

  • Replace: the table becomes exactly what the URL holds now.
  • Upsert on a key column: rows whose key matches are updated, new keys are added, and rows the source no longer has are kept.

A sync checks everything before it writes anything, so a bad download leaves the table as it was.

Link columns

A link column points at rows of another of your tables, like the customer of an order. Change a column's type to Link, pick the table it links to and the column to show for each linked row.

Click a link cell to pick the rows of the linked table it points at: type to search them by the column it shows, choose rows, then Save. A cell can link to several rows. Click one of the cell's linked rows to open the linked table instead. In the API the cell is an array of the linked rows' _id values (or null); add expand=<column> to a Get, Search or Query call to get the linked rows themselves.

Fill links by matching

When both tables already share a value, like an Email in your signups and in your contacts, a link column can fill itself. Save the link column, then open its link settings again (in Edit Columns, its type menu → Link). Under Fill links by matching, choose a column of this table and the column of the linked table it should match (a column with the same name is chosen for you), then click Find matches.

You see how many rows will be linked, how many have no match, how many match more than one row and how many already have links. Nothing changes until you click Link rows.

  • Text matches ignoring capitals and spaces at either end; numbers match by value and dates by the same moment. Empty values never match.
  • A row that matches several rows is linked to all of them (at most 50).
  • Only empty link cells are filled: cells you already linked are left as they are.
  • It fills the column once. Rows you add or change later aren't matched again; run it again to fill them.

When rows or tables are deleted

  • Deleting rows removes them from every link that pointed at them.
  • Deleting the linked table empties those cells and turns the link columns into text columns.

Link columns are left out of forms.

The API

Every table can be read and written at https://api.invokedb.com/v1. Send your API key as Authorization: Bearer YOUR_API_KEY, and name the table with ?table= (its name, any case).

Call What it does
GET /get Rows, paged with skip and limit
POST /search Rows matching simple column filters
POST /query Rows with filters (eq, ne, gt, gte, lt, lte, contains, in, empty), sort, chosen fields and cursor paging
POST /count How many rows match the same filters
POST /create Add rows (an array of objects)
PUT /update Change rows, each with its _id
POST /delete Delete rows (an array of _ids)
GET /openapi The table's OpenAPI 3 spec

An example query

curl -X POST -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  "https://api.invokedb.com/v1/query?table=people" \
  -d '{"filters": [{"column": "age", "op": "gte", "value": 21}],
       "sort": ["-age"], "limit": 50}'

The answer is { "data": [...], "next_cursor": "..." }. Send the same body with cursor set to next_cursor for the next page; next_cursor is null on the last one.

Docs for each table

In the app, a table's API button shows its own endpoints, its columns and their types, examples in curl, JavaScript (fetch and the invokedb npm client) and Python, a Try it button, and its OpenAPI spec for tools like Postman. The Api page in the app's menu documents every call in full.

Errors

A bad request is answered with a 4xx status and a message saying what's wrong (a missing table, an unknown column, a value of the wrong type). A 403 means the key can't do that, or a limit was reached.

API keys

A key lets code use your tables through the API. Make them on the Account page in API keys. You can have up to 20 live keys, for example one per app or integration.

Making a key

  • Name: to tell your keys apart.
  • Access: Read only (get, search, query, count) or Read and write (also create, update and delete).
  • Tables: every table, or only the ones you pick. Calls on other tables are refused.

The key is shown once, when you make it. We only keep a fingerprint of it, so we can't show it again: if you lose it, make a new one.

Keeping keys safe

Treat a key like a password. Don't put a read-and-write key in a web page or a mobile app, where anyone can read it; use a read-only key limited to the tables the page needs, or call the API from your server.

Revoking

Revoke stops a key at once. Revoked keys are hidden behind a toggle and removed after 7 days.

AI agents (MCP)

AI agents such as Claude, ChatGPT and Cursor can use your tables directly through InvokeDB's MCP server (the Model Context Protocol, the standard way agents connect to tools). Connect it with an API key and the agent sees your tables and works with their rows. New to it? The agent quickstart goes from sign-up to a first prompt, step by step.

Connecting an agent

On the Account page, in API keys, the Use with AI agents box (click its title to open it) has the server's address and the setup to paste. It opens by itself right after you make a key, with the key filled in. For Claude Code: 

claude mcp add --transport http invokedb https://api.invokedb.com/mcp \
  --header "Authorization: Bearer YOUR_API_KEY"

Cursor, VS Code and a project's .mcp.json take the same address and header as JSON; the Account page shows it.

What an agent can do

  • list_tables and describe_table: the tables the key can use, their columns and row counts.
  • query_rows and count_rows: filters, sorting and paging, like the API's /query.
  • list_views and query_view: the saved views you made in the app. A grid view gives its rows with its filters, sort and visible columns; a kanban, chart, calendar or map view gives what the app draws (groups, points or events). Any key that can use the view's table can read its views.
  • create_rows, update_rows and delete_rows: only with a Read and write key, up to 100 rows a call.
  • create_table and add_columns: make a new table (optionally in a folder) and add columns to one. Columns are text, number or date; link and AI columns are set up in the app. Only with a Read and write key for all tables, and within your plan's table and column limits.

Staying in charge

  • The key decides: a Read only key can't change anything, and a key limited to some tables doesn't see the others or make new ones.
  • Every change an agent makes is in the table's History, under the key's name, and fires your webhooks like any other change.
  • Each tool call counts as one API call, against your plan's monthly calls and rate limit; a key's own limit and request log apply too.
  • Give an agent its own key, so you can see what it did and revoke it on its own.

Webhooks

A webhook tells your server when rows change. Open a table, click Webhooks, give the URL to call and pick the events: row.created, row.updated and row.deleted. Changes made in the app, by the API and by forms are sent; CSV uploads and URL syncs aren't.

What's sent

A POST with a JSON body:

{
  "id": "whd_...",
  "event": "row.created",
  "created_at": "2026-11-25T10:00:00.000Z",
  "webhook_id": "wh_...",
  "table": { "id": 11, "name": "people" },
  "rows": [{ "_id": "...", "name": "Ada", "age": 36 }]
}

A change to more than 100 rows is sent as several deliveries. Send test event sends a ping event with no rows.

Checking the signature

Each delivery has an InvokeDB-Signature: t=<unix time>,v1=<hex> header. v1 is the HMAC-SHA256, with the webhook's secret (whsec_..., shown in the dialog), of <t>.<raw body>. Compute it, compare, and reject deliveries whose t is more than 5 minutes off. 

const crypto = require('crypto');

function verify(secret, raw_body, header) {
  const parts = Object.fromEntries(header.split(',').map(p => p.split('=')));
  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${parts.t}.${raw_body}`)
    .digest('hex');
  const fresh = Math.abs(Date.now() / 1000 - Number(parts.t)) < 300;
  const a = Buffer.from(expected);
  const b = Buffer.from(parts.v1 || '');
  return fresh && a.length === b.length && crypto.timingSafeEqual(a, b);
}

Retries and the log

Answer with any 2xx status within 10 seconds. Otherwise the delivery is tried again after 5 s, 30 s, 2 min, 10 min, 1 hour and 6 hours (7 tries), then marked failed. The dialog shows each webhook's last 50 deliveries, kept for 7 days. Webhooks can't call private or local addresses, and redirects aren't followed.

Forms

A form is a public page that adds a row to a table each time someone fills it in, with no account needed. Open a table and click Forms.

Setting it up

  • A title, a description, and the columns to ask for, each with its own label, a line of help and whether it's required.
  • The submit button's text, and a thank-you message or a URL to send people to afterwards.
  • Open or closed: a closed form says so and takes no answers.

Answers are checked against the column types (a number for a Number column, a date for a Date column). Link columns aren't asked for.

Sharing

Each form has a link (/f/...) to share, and code to embed it in your own site in an iframe. Deleting the form or its table turns the link off. The link follows the visitor's light or dark setting; the embedded form is light, or dark if you add &theme=dark to the end of its src.

Spam

Forms have a hidden field that bots fill in and people don't, and limit how often one visitor, and everyone together, can submit. Submissions count against the table's row limit and trigger its webhooks.

Views

A view is a saved way of looking at a table. Open the Views menu on the grid's top bar, then Save or manage views.... All rows goes back to the plain grid. A table can have up to 50 views.

  • Grid: the grid's current filters, sort and hidden columns, saved under a name.
  • Kanban: a card per row, in a column per value of a text or number column (a status, say). Drag a card to another column to change that value.
  • Chart: a bar, line or pie chart that counts rows, or sums a number column, per value of a column.
  • Calendar: rows on a month calendar by a date column.
  • Map: rows as points, from a latitude and a longitude number column. Each point links to OpenStreetMap; rows without a position are counted but not drawn.

Every view can have filters of its own.

Ask AI

Open a table and click Ask AI to work with it in plain English. The AI reads your columns and, only when it needs them, some rows. It can:

  • Answer questions: "How many orders over $100 came from Paris?" It runs a query and shows it, so you can check its answer.
  • Propose rows: "Add 20 sample customers." The rows appear in the grid as new rows; nothing is saved until you click Save.
  • Use your other tables: "Add 10 rows using the emails from signups." The AI knows the names and columns of your other tables and can read their rows (never another account's), but it only ever changes the table you opened it on. The rows it read and the API call that returns them are shown, and the rows it proposes from them are reviewed and saved like any other (they count as AI rows).
  • Edit rows: "Capitalise the city names" or "Set status to done where due is before today." You see every row before and after first, and can undo the last edit.
  • Clean up (the button next to Ask): looks through the first 500 rows for stray spaces, invalid emails and phone numbers, numbers and dates written in different formats, the same value written differently, and duplicate rows. Each problem comes with a fix you tick and check before you click Apply; duplicates are deleted only if you tick them. Undo puts the cells back, and deleted rows back as new rows. Tables with link columns aren't checked for duplicate rows. A scan uses one question.
  • Paste text: paste an email, a table copied from a PDF or a badly formatted CSV (up to 20,000 characters; pasting several lines into the question box opens it too), and click Make rows. The AI copies the records into the table's columns, leaving empty what the text doesn't say, and you review them like proposed rows: add them to the grid, check or edit them, then Save. A paste uses one question, and the rows it makes (at most 200) count as AI rows.

Table from a Description (AI), under + on the Tables page, designs a new table, with columns and sample rows, from a sentence.

It can use your existing tables: "A table of follow-ups for the emails in crm_contacts." The AI knows the names and columns of your tables (never another account's), so it can reuse a column's name and type, and it reads the table you name and fills the rows with its values rather than making them up; what the table doesn't hold and you didn't ask for is left empty. It only reads your tables, and nothing is made until you click Create table. The design counts as one AI row, and every row in the preview counts too, copied or made up; reading a table costs nothing more.

AI columns

An AI column is a column the AI fills in for you, row by row, from other columns of the row: "summarise the notes", "classify the feedback as positive, neutral or negative", "score the lead from 1 to 5". Open a table, then More () → AI columns: pick the column to fill, the columns it reads and what to put in it.

Before it fills, it tells you how many AI rows it will use: one for every cell it fills (rows whose columns are empty are left empty for free). It fills in the background, and the grid shows the cells as they're done. After that, when a row is added or the columns the AI column reads change (in the app, through the API or a form), that row's cell is filled again by itself; changes to other columns don't use anything. Changing the prompt or the columns it reads asks you to fill it again. If your AI rows run out, the column stops: the cells left show a note, and you can fill them once your allowance renews. Stop using AI keeps the column and its values as an ordinary column.

Allowance

Each plan includes a number of AI questions and AI rows a month (the Free plan: 10 questions and 50 rows). The dialog shows what's left. AI needs a confirmed email address. AI can make mistakes: check its answers and edits before you rely on them.

Your account

Signing in

Sign in with your email and password, or with Google or GitHub. Forgot your password? Reset it by email.

Confirming your email

After signing up with an email we send a link to confirm it (it works for 24 hours). Until then a banner in the app offers to send it again, and you can't create tables or use API keys. Accounts made with Google or GitHub are confirmed already.

The Account page

In the app, the account menu at the top right (your initial and email) has Account settings, Contact support and Sign out. Account settings opens the Account page, with its sections in a list on the left (a row of tabs at the top on a phone):

  • Plan & usage: your plan, how much of each of its limits you use, upgrading and billing.
  • API keys: your API keys, their last requests and the setup for AI agents.
  • Profile: your name and email.
  • Security: change your password and turn on two-factor sign-in.
  • History: every change to your tables, columns and keys.
  • Data: export your data or delete the account.

Each section has its own address, so you can bookmark one or go back to the one before.

Deleting your account

Delete Account, at the bottom of the Account page's Data section, deletes the account and all its data at once: every table with its rows and columns, your forms, views, webhooks, URL sources, API keys, history, AI usage and exports. You're signed out everywhere, and the email address can be used for a new account. It can't be undone, so use Export Your Data first if you want a copy. If you're on a paid plan, deleting the account cancels it first.

Plans and billing

Under Plan & usage on the Account page, pick Monthly or Yearly and click Get Starter or Get Pro (or Choose on the pricing page). You pay on Stripe's secure checkout page; InvokeDB never sees your card. Your new limits apply as soon as Stripe confirms the payment, usually within seconds. Manage billing opens Stripe's billing page, where you can switch between Starter and Pro, update your card, see invoices or cancel. A cancelled plan runs until the end of the period you've paid for, then the account moves to Free. If a payment fails, everything keeps working for 14 days while the card is retried; a banner says so. After that the account moves to Free (see limits for what happens if it holds more than Free allows).

Light and dark

Theme in the account menu switches the app between Light and Dark. System, the default, follows your device's setting and changes with it. The choice is saved on your account, so it follows you to other devices. These pages and the public site always follow your device's setting. A form embedded on another site stays light unless its link ends in &theme=dark.

When support changes your account

If you ask us to, InvokeDB support can change your plan, lock or unlock your account, send a new verification email or turn two-factor sign-in off after checking it's you. Each change is listed under History on the Account page, by "InvokeDB admin". Support sees your tables' names, sizes and row counts and your API keys' first characters, never your rows or the keys themselves. A locked account can still sign in and read its data, but can't change it; the reason is shown under Plan & usage.

Getting help

Use the contact form (Contact support in the account menu opens it too), or the help button next to it for these pages.

Limits

Your plan sets how many tables you can have, how many rows they hold (in all, and in one table), how much storage they take, how many columns a table has, how many API calls you can make a month and how fast, how big a CSV upload can be, and how many URL imports, webhooks, forms and views you can have. See every plan's numbers on Pricing, and yours, with how much of each you use, under Plan & usage on the Account page.

Something that would go over a limit is refused with a 403 (413 for an upload that's too big) whose body says "code": "plan_limit", which limit, the cap and an upgrade_url; the app shows a notice with a link to your usage. Nothing is written, and the rows you have stay. Past the monthly API calls, the API answers 429 until the 1st of the next month (UTC); past the rate limit, 429 with a Retry-After header. The app itself keeps working either way.

Over your plan's limits

If your account holds more than your plan allows (after moving to a smaller plan, or when a payment lapses), it becomes read-only: you can still read your data, export it and delete it, in the app and through the API, but adding or changing anything (rows, columns, tables, uploads, URL syncs, form submissions, new webhooks, forms and views) is refused with a 403 whose body says "code": "plan_read_only" and which limits you're over. Nothing is deleted. As soon as you've deleted down to the limits (or upgraded), you can write again. When a payment fails, everything keeps working for 14 days first, with a banner in the app.

Unused free accounts

A free account with no sign-in and no API call for 6 months is deleted, with all its tables and data. We email you at 5 months and again a week before; signing in or making an API call keeps the account. Paid accounts are never deleted for not being used.
