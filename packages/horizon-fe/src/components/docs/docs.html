[POST] Search

URL

{{ base_url }}/search

?table={table}

&skip={skip}

&limit={limit}

&sort_by={sort_by}

&sort_dir={sort_dir}


Headers

Bearer token


Query Params

name of the table

amount of records to skip

amount of records to return

field to sort

direction to sort


Body

The body of the POST is used to pass the filter object. Any column can be filtered against.

A filter object uses the following format.

                            
{
    column_one: {
        value: ...,
        type: ...,
        case: ... // Text columns only
    },
    column_two: {
        ...
    }
}
Filters by column type

There are currently 3 column types in InvokeDB: Text, Number and Date. Listed below are the filter object types for each.

Text Filter

                                
{
    value: <string>,
    type: <string>, // equals/contains
    case: <string> // sensitive/insensitive, default: sensitive
}

Number Filter

                                
{
    value: <number>,
    type: <string>, // equals/greaterThan/lessThan/greaterThanOrEqual/lessThanOrEqual
}

Date Filter

                                
{
    value: <string/date>,
    type: <string>, // equals/greaterThan/lessThan/greaterThanOrEqual/lessThanOrEqual
}

1 Column, multiple conditions

To pass multiple conditions to the same field you must use an array instead of an object for the field value as follows: 

                            
{
    column_one: [{
        value: ...,
        type: ...
    }, {
        value: ...,
        type: ...
    }]
}

Note: This is similar to an AND select in sql. To do an OR see the next section.


Multiple filters (OR)

By default multiple filters are queried using an AND operator. To query the table as an OR instead, use the $or operator as follows: 

                            
{
    $or: {
        column_one: [{
            value: ...,
            type: ...
        }, {
            value: ...,
            type: ...
        }],
        column_two: {
            value: ...,
            type: ...
        }
    }
}

The above will perform an OR query on the both columns as well as both conditions for the first column.

[POST] Query

URL

{{ base_url }}/query?table={table}


Query Params

name of the table

camelCase or snakeCase column names


Body

A JSON object. Every key is optional; send {} for the first page of every row. 

                            
{
    // Rows must match every filter ("match": "any" for any of them)
    filters: [
        { column: 'age', op: 'gte', value: 21 },
        { column: 'city', op: 'in', value: ['Paris', 'Rome'] }
    ],
    match: 'all',
    // Column names, "-name" for descending, or { column, dir }
    sort: ['-age', 'last_name'],
    // Only these columns come back (with _id)
    fields: ['first_name', 'last_name', 'age'],
    // 1 to 1000, default 100
    limit: 50,
    // next_cursor from the previous page, for the next one
    cursor: null
}
Operators

equals, not equals. On text, eq is exact and case-sensitive

greater than (or equal), less than (or equal)

any of an array of up to 100 values

text columns only; case-insensitive unless the filter has case: 'sensitive'

true for empty cells, false for filled ones

Values must match the column's type: a number for Number columns, a date string such as 2024-01-15 for Date columns, text for Text columns. _id takes eq, ne and in. A wrong column, operator or value is a 400 with a message saying which.


Response

{ data: [...rows], next_cursor }. next_cursor is null on the last page. Send the same body with cursor set to it for the next page: unlike skip, pages stay in order when rows are added or deleted. Rows are ordered by the sort columns, then _id.

Filters on a column marked Indexed (Edit Columns) use its index. Send "explain": true to check: the response is { explain: { uses_index, index_columns } } instead of rows.
